What is DNS?
DNS (Domain Name System) is a distributed database that translates human-readable domain names into IP addresses. Often called the "phone book of the internet." Operates over Port 53 (UDP/TCP).

🎭 DNS SPOOFING LAB

Simulation of user redirection via forged DNS responses.

How it works:
The attacker sends a forged UDP packet before the legitimate DNS reply arrives. If the Transaction ID (16-bit value, range 0–65535) is guessed correctly, the resolver writes the attacker's fake IP into its cache. All users are then silently redirected to the malicious server.

📡 DNS AMPLIFICATION LAB

Generating massive traffic from tiny queries — up to 75x amplified DDoS.

Amplification factor:
DNS ANY query: ~40 bytes → Response: ~3,000 bytes = 75x amplification!
The attacker sends small queries to open resolvers while spoofing the victim's source IP. All large responses are directed at the victim, saturating their bandwidth.

💾 DNS CACHE POISONING

Kaminsky Attack — injecting forged records into a DNS resolver's cache.

The Kaminsky Attack (2008):
Discovered by Dan Kaminsky, this critical vulnerability exploits the 16-bit Transaction ID space (0–65535) combined with source port randomization. The attacker fires thousands of forged replies simultaneously, racing to match the correct TxID before the legitimate DNS response arrives.

❌ NXDOMAIN ATTACK LAB

Overloading DNS infrastructure with queries for non-existent domains.

In an NXDOMAIN attack, the attacker floods the DNS server with queries for domains that don't exist. For every query, the resolver must contact root/TLD servers upstream — dramatically increasing upstream load and starving legitimate queries.

🛡 DEFENSE STRATEGIES

Industry-standard techniques for protecting DNS infrastructure.

🔐
DNSSEC
Cryptographic signing of DNS responses. The most effective defense against Cache Poisoning. Uses RRSIG, NSEC, and DS record types.
dnssec-keygen -a RSASHA256 -b 2048 -n ZONE example.com
dnssec-signzone -A -3 $(head -c 1000 /dev/random \
  | sha1sum | cut -b 1-16) example.com
📊
Rate Limiting (RRL)
BIND Response Rate Limiting — throttles excessive queries from the same IP. Highly effective against amplification and flood attacks.
rate-limit {
  responses-per-second 10;
  errors-per-second 5;
  nxdomains-per-second 5;
  slip 2;
};
🔥
DNS Firewall (RPZ)
Response Policy Zones — blocks resolution of malicious domains. Widely deployed at the ISP and enterprise level.
response-policy { zone "rpz.blocklist"; };
; RPZ zone file:
malware.example.com CNAME .
*.malware.example.com CNAME .
🌐
BCP38 Anti-Spoofing
ISP-level ingress filtering to prevent IP address spoofing. Eliminates the root cause that enables amplification attacks.
# Cisco IOS
ip verify unicast source reachable-via rx
# Linux iptables
-A PREROUTING -m rpfilter --invert -j DROP
